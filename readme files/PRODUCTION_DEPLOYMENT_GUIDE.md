## 🔐 Environment Configuration

### Backend Environment Variables

**Create `.env.production` in `backend/`:**

```env
# Database
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/health_surveillance_db?retryWrites=true&w=majority

# Authentication
JWT_SECRET=your-super-secret-jwt-key-min-32-chars
JWT_EXPIRY=7d

# AI Provider
AI_PROVIDER=python          # Options: python, gemini, openai
PYTHON_ML_URL=http://ml-service:5001

# Optional: Gemini API
GEMINI_API_KEY=your-gemini-api-key

# Optional: OpenAI API
OPENAI_API_KEY=your-openai-api-key

# Server
PORT=5000
NODE_ENV=production
LOG_LEVEL=info

# Email Service (SendGrid)
SENDGRID_API_KEY=your-sendgrid-api-key
SENDGRID_FROM_EMAIL=noreply@yourdomain.com

# CORS & Security
CORS_ORIGIN=https://yourdomain.com
RATE_LIMIT_WINDOW=15
RATE_LIMIT_MAX_REQUESTS=100

# Monitoring
SENTRY_DSN=your-sentry-dsn-for-error-tracking
```

## 🗄️ Database Setup (MongoDB Atlas)

### Step 1: Create MongoDB Atlas Cluster

1. Go to https://www.mongodb.com/cloud/atlas
2. Sign up or login
3. Create new project: "Health Surveillance"
4. Create cluster: Select "M0 Free" tier
5. Create admin user: `admin` / strong password
6. Add IP whitelist: `0.0.0.0/0` (or specific IPs)
7. Get connection string: `mongodb+srv://admin:password@cluster.mongodb.net/`

### Step 2: Create Database Collections

```javascript
// In MongoDB Atlas console
// Create database: health_surveillance_db

// Collections are auto-created by Mongoose, but you can pre-create:
db.createCollection("users")
db.createCollection("healthreports")
db.createCollection("outbreakpredictions")

// Create indexes for performance
db.healthreports.createIndex({ "district": 1 })
db.healthreports.createIndex({ "date": -1 })
db.healthreports.createIndex({ "reportedBy": 1 })
db.users.createIndex({ "email": 1 }, { unique: true })
db.outbreakpredictions.createIndex({ "district": 1, "weekStart": -1 })
```

### Step 3: Seed Production Data

```bash
# Set environment variable
export MONGODB_URI="your-production-uri"

# Run seeding script
npm run seed

# Verify
mongodb-cli "your-connection-string" --eval "db.users.count()"
```

## 🌐 Deployment Platforms

### Option 1: Railway.app (Recommended - Easiest)

#### Backend Deployment

1. **Push to GitHub**
   ```bash
   git add .
   git commit -m "Ready for production deployment"
   git push origin main
   ```

2. **Create Railway Project**
   - Go to https://railway.app
   - Login with GitHub
   - Click "New Project"
   - Select "GitHub Repo"
   - Choose your repository
   - Select "backend" directory

3. **Configure Environment Variables**
   - Go to Variables tab
   - Add all variables from `.env.production`
   - Don't include sensitive keys in repo, add them in Railway UI

4. **Add MongoDB Service**
   - Click "Add"
   - Select "MongoDB"
   - Railway creates managed MongoDB
   - Copy `MONGODB_URI` to project variables

5. **Deploy**
   - Click "Deploy"
   - Wait for build (2-3 minutes)
   - Get production URL: `https://your-app.railway.app`

#### Python ML Service Deployment

1. **Create New Railway Project**
   - Click "New Project"
   - Select GitHub Repo
   - Select `backend/ml-service` directory

2. **Configure**
   - Set Python version: 3.9
   - Add variables: PORT=5001
   - Deploy

3. **Update Backend**
   - Set `PYTHON_ML_URL=https://ml-service.railway.app` in backend variables

#### Frontend Deployment

1. **Deploy to Vercel**
   - Go to https://vercel.com
   - Import GitHub repository
   - Select `frontend` directory
   - Add environment variables
   - Set `NEXT_PUBLIC_API_URL=https://api.railway.app`
   - Deploy (automatic on push)

### Option 2: Docker Containerization

#### Create Backend Dockerfile

**`backend/Dockerfile`:**

```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --production

COPY . .

ENV NODE_ENV=production

EXPOSE 5000

CMD ["node", "server.js"]
```

#### Create Python ML Dockerfile

**`backend/ml-service/Dockerfile`:**

```dockerfile
FROM python:3.9-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

ENV FLASK_ENV=production

EXPOSE 5001

CMD ["gunicorn", "--bind", "0.0.0.0:5001", "app:app"]
```

#### Create Frontend Dockerfile

**`frontend/Dockerfile`:**

```dockerfile
FROM node:18-alpine AS builder

WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .

RUN npm run build

FROM node:18-alpine

WORKDIR /app

COPY --from=builder /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./
COPY public ./public

ENV NODE_ENV=production

EXPOSE 3000

CMD ["npm", "run", "start"]
```

#### Docker Compose

**`docker-compose.yml`:**

```yaml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "5000:5000"
    environment:
      MONGODB_URI: mongodb://mongo:27017/health_surveillance_db
      PYTHON_ML_URL: http://ml-service:5001
      JWT_SECRET: ${JWT_SECRET}
    depends_on:
      - mongo
      - ml-service
    restart: always

  ml-service:
    build: ./backend/ml-service
    ports:
      - "5001:5001"
    environment:
      PORT: 5001
    restart: always

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    environment:
      NEXT_PUBLIC_API_URL: http://backend:5000
    depends_on:
      - backend
    restart: always

  mongo:
    image: mongo:5.0
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db
    restart: always

volumes:
  mongo_data:
```

#### Deploy with Docker

```bash
# Build images
docker-compose build

# Start services
docker-compose up -d

# Check status
docker-compose ps

# View logs
docker-compose logs -f
```

## 📧 Email Notification Setup

### SendGrid Integration

1. **Sign up at SendGrid:**
   - https://sendgrid.com
   - Create account
   - Verify sender email
   - Create API key

2. **Add to Backend**

**`backend/services/emailService.js`:**

```javascript
const sgMail = require('@sendgrid/mail');
sgMail.setApiKey(process.env.SENDGRID_API_KEY);

async function sendAlertEmail(officialEmail, alertData) {
  const msg = {
    to: officialEmail,
    from: process.env.SENDGRID_FROM_EMAIL,
    subject: `HIGH RISK ALERT: ${alertData.predictedDisease} in ${alertData.district}`,
    html: `
      <h2>Disease Outbreak Alert</h2>
      <p><strong>Risk Level:</strong> ${alertData.riskLevel}</p>
      <p><strong>Disease:</strong> ${alertData.predictedDisease}</p>
      <p><strong>District:</strong> ${alertData.district}</p>
      <p><strong>Confidence:</strong> ${alertData.confidenceScore}%</p>
      <p>${alertData.explanation}</p>
      <a href="https://yourdomain.com/dashboard">View Dashboard</a>
    `
  };
  
  await sgMail.send(msg);
}

module.exports = { sendAlertEmail };
```

3. **Install SendGrid**

```bash
npm install @sendgrid/mail
```

4. **Trigger on HIGH Risk**

```javascript
// In routes/predictions.js
if (prediction.riskLevel === 'HIGH') {
  await sendAlertEmail(user.email, prediction);
}
```

## 🔄 CI/CD Pipeline

### GitHub Actions Workflow

**`.github/workflows/deploy.yml`:**

```yaml
name: Deploy to Production

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install backend dependencies
        run: |
          cd backend
          npm install
      
      - name: Run backend tests
        run: |
          cd backend
          npm test
      
      - name: Install frontend dependencies
        run: |
          cd frontend
          npm install
      
      - name: Run frontend tests
        run: |
          cd frontend
          npm test

  deploy:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Deploy to Railway
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}
        run: |
          npm i -g @railway/cli
          railway up
          
      - name: Notify Slack
        if: success()
        run: |
          # Optional: Send deployment notification
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -d "{\"text\": \"✅ Deployment successful\"}"
```

## 🔒 Security Hardening

### SSL/TLS Certificates

- Railway, Vercel, and Render auto-generate SSL
- Use https://yourdomain.com (not http)
- Enforce HTTPS redirect

### Security Headers

**Backend (`server.js`):**

```javascript
const helmet = require('helmet');
app.use(helmet());
app.use(express.json({ limit: '10mb' }));
app.use(express.urlencoded({ limit: '10mb', extended: true }));
```

**Frontend (Next.js):**

```javascript
// next.config.js
module.exports = {
  async headers() {
    return [
      {
        source: '/:path*',
        headers: [
          { key: 'Strict-Transport-Security', value: 'max-age=31536000' },
          { key: 'X-Content-Type-Options', value: 'nosniff' },
          { key: 'X-Frame-Options', value: 'DENY' },
          { key: 'X-XSS-Protection', value: '1; mode=block' }
        ]
      }
    ];
  }
};
```

### Rate Limiting in Production

```javascript
const rateLimit = require('express-rate-limit');

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100,
  message: 'Too many requests',
  standardHeaders: true,
  legacyHeaders: false
});

app.use('/api/', limiter);
```

## 📈 Scaling Configuration

### Horizontal Scaling (Multiple Instances)

**Railway Configuration:**
1. Go to Service Settings
2. Set "Min Instances": 2
3. Set "Max Instances": 10
4. Set "CPU": 0.5 vCPU
5. Set "Memory": 512 MB
6. Enable "Auto-Scale"

### Database Scaling

**MongoDB Atlas Scaling:**
1. Go to Cluster Settings
2. Upgrade tier if needed (M2+)
3. Enable Read Replicas
4. Monitor storage usage
